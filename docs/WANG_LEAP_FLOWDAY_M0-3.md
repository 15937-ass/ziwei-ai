# M0-3：王亭之闰月流日安法逐日对照审计（2026-11-13）

**结论状态：存在系统性的 SOURCE-INTERPRETATION-DIVERGENCE，仍未被认定为 SOURCE-CERTIFIED。**

## 1. 原始依据与不可混同的两条规则

主资料：王亭之《中州派紫微斗数初级讲义》，安星法印刷第58页（见第一轮[安星审计](WANG_ANXING_AUDIT_2026-11-13.md)）。

- **一般流日法**：以流月命宫为初一，沿地支顺数；十三、二十五返回流月命宫。原文的「三月流月命宫在酉，十五日在亥」可由 +14 模12 单独复核。
- **闰月特别法**：原文交代闰月前半归前月、后半归下月，并专门以闰三月举例，称原三月30日后加前半15日、合计45日连续顺推，下月亦存在额外日数累计。此处存在将自然语言严格转为算法的解释步骤，**不能把该步骤和王亭之逐日原盘实例混为一谈**。

审计将以下两种实现并排测试：

| 候选 | 规则 | 验证含义 |
| --- | --- | --- |
| A：原农历日数重置 | 每个自然农历月份都按当天日数重新从当期流月宫推算；闰月的前十五/后半改变流月宫，但不延续前月已经计过的日数。 | **iztro 2.6.5 当前可观测行为**；不是已经证明的王亭之闰月流日法 |
| B：原典连续累计的直接解释 | 闰月前十五日接续此前本月29/30日；后半归下个月，后续正常月接续闰月后半实际剩余的14/15日。 | **源文形式化候选**；没有独立原典逐日完整命盘证明，不能直接晋升正式版 |

这两种算法均使用已经独立通过测试的斗君与流月命宫；比较的**唯一变量是流日偏移量**。

- 2017：<https://www.hko.gov.hk/tc/gts/time/calendar/pdf/files/2017.pdf>

程序的逐日转换目前使用 `lunar-typescript`；它也是 iztro 的间接依赖，**不是独立天文历表**，所以上述 HKO 边界校验是必要的额外证据。不能因这32个锚点通过，就宣称相关年份的每一天历法都已经独立认证。

## 3. 批量实验实际结果

CI 实测（iztro@2.6.5、zhongzhou、固定十干四化、两张出生盘）：

| 指标 | 对照数量 | 一致 |
| --- | ---: | ---: |
| 斗君/流月命宫关系 | 708 | **708** |
| iztro 流日与原日数重置算法 | 708 | **708** |
| iztro 流日与闰月连续累计候选算法 | 708 | **238** |
| iztro 相对连续累计候选算法的差异 | 708 | **470** |

各年两张盘累计与原文连续解释不一致的断言：2017年118，2020年118，2023年116，2025年118。

这些差异集中在**闰月与紧随其后的正常月**。闰月前一个正常月全部符合一般流日规则。30天闰月（2017）和29天闰月（2020/2023/2025）均复现同种差异，不是原先14日小样本的偶然性。

每个日期的历法、流月、原典候选流日位置、iztro实际流日位置及两个候选是否匹配，都在 CI Artifact `wang_leap_day_full_grid.json` 里。

**注意：470是与来源形式化候选之间的差异，不是经独立原典实例认证的「470处软件错误」。**

## 4. API 诊断与商用风险

不要混淆三个字段：

- `monthly.earthlyBranch`：流月干支中的地支；
- `monthly.index`：流月命宫在本命盘宫位数组的索引；
- `daily.index`：引擎计算的流日命宫索引，**目前反映简单按原日期起算的算法**。

这次审计**没有**修改正式 `ChartSnapshot`、iztro 动态计算或产品输出。

对于用户指定王亭之中州派口径的商业产品，在未裁定前建议：

1. 原局、已认证的常规流月流日仍可正常展示；
2. 对闰月及其后一正常月的**流日命宫/四化依赖**须显示 `UNRESOLVED_WANG_LEAP_FLOWDAY`，不得在正式推断管线默默使用 iztro 原结果或擅自改为候选算法；
3. 若使用者只请求十二宫原局，不应因为流日研究缺口停掉基础排盘；
4. 不将研究候选数据写为规范知识、训练真值或大模型可直接引用的确定事实。

## 5. 下一步的验收要求

- 找到第二个具有完整年/月/日日期及流日命宫安法的王亭之原典实例，最好涉及闰月15/16及下个月；或者由原书直接提供可无歧义形式化的逐日实例链。
- 对第二资料来源与《初级讲义》第58页的文字进行版次、勘误与流派口径核对。
- 若原典差异得到确认，在**独立中州派动态计算适配层**实现有版本的候选算法，不修改上游 iztro 包本体，不事后涂改其原始结果；必须通过两套口径的双路径回归。
- 在此以前，商用中州派流日功能不得标记为 `SOURCE-CERTIFIED`。

版本化门禁：`tools/audit_wang_gate.mjs` 记录固定 iztro 2.6.5 的现有差异模式，**仅用于暴露异常变化，不表示批准这些差异**。
