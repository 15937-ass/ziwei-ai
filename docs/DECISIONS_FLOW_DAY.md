# ADR-001 · 流日算法使用 iztro 原生实现（当前产品基线）

决策日期：2026-11-13 · 状态：**接受，暂不重新实现**

## 决策

对于当前项目，流日（包括闰月流日）统一沿用固定版本 `iztro@2.6.5` 的原生 `horoscope().daily` 计算。**不对其日数进行后处理，不引入未经裁定的「王亭之连续计日」候选算法。**

原因：项目主要目标是原局、星系组合、三方四正、大限、流年的知识增强推断；流日属于较低优先级的功能，不值得阻塞知识库与 LLM 原型。该决策不会更改王亭之十干四化、子时00:00换日、闰月基础安盘口径，也不改变出生地真太阳时处理。

本决策是**工程产品默认值**，并非证明 iztro 的闰月流日完全符合王亭之第58页。任何报告都不得称其为「王亭之所有流日安法已认证」。

## 在项目里的实现位置

- `src/ziwei/chart/contract.py::FLOW_DAY_POLICY` 保存显式决策元数据，暂不改动原局 `ChartSnapshot` 的 Schema。
- iztro 已有 `horoscope().daily`；当前尚没有对外提供流日接口或付费流日产品，所以本次不建立新适配器、也不改动核心排盘接口。
- 未来如果实现动态推断接口，必须直接消费 `horoscope().daily.index` 所映射的**本命盘宫位**，并记录 iztro 版本和本策略 ID。注意 `daily.earthlyBranch` 是干支字段，**不能代替流日命宫位置**。
- `tools/audit_wang_gate.mjs` 继续保证 iztro 原生日序不意外改变；原典连续计日的测试仍归档供研究，但不要求与之相等，亦不以候选差异数作为发布阻断条件。

## 已有研究证据与后续取舍

- `docs/WANG_LEAP_FLOWDAY_M0-3.md` 记录四个闰月、两张出生盘的708项完整测试；iztro 与原生按农历日数重置的模型708/708一致，与王亭之第58页连续累计的候选形式化解释只有238/708一致。
- 候选式解释属于学术未决问题；已保留页面证据与测试，不属于当前 M0/M1 主线的必过条件。
- **触发重审**：实际准备上线「流日精批」功能，获得王亭之带有闰月完整流日宫位的可靠案例，或升级 iztro 版本导致原生行为变化。发生其中之一，再重新评估独立中州派动态适配器。

## 下一步

释放流日规则审计占用的开发注意力，继续推进**原局 ChartSnapshot 的稳定契约 → 基础知识库及来源规则 → LLM 检索推断闭环**。流年和大限仍需正常校验，不受本决策降级。
